Hướng dẫn triển khai cms-api (.NET + PostgreSQL)

Đưa bản .NET của euni-api-mock lên máy chủ thật, thay thế mock Node mà euni-admin và euni-public không phải sửa. Làm lần lượt từng bước; mỗi bước có lệnh kiểm tra.

1 API · 1 databaseRow-Level Security theo tenant2 role DB: cms_app · cms_adminOutbox worker cùng tiến trình

1 Tổng quan

API là một ứng dụng ASP.NET Core duy nhất, kết nối một database PostgreSQL. Mọi request nghiệp vụ đi qua role cms_app (bị RLS giới hạn theo tenant); các tác vụ dựng lược đồ, nạp dữ liệu mẫu, sao lưu và worker outbox đi qua role cms_admin.

Thành phầnViệc của nó
euni-api-dotnet/src/HUMG.CMS.ApiỨng dụng chạy: HTTP, xác định tenant, lỗi chuẩn hóa
database/v2/schema.sql + amendments.sqlLược đồ quan hệ (RLS, bảng con đã vá) — ứng dụng tự áp khi khởi động
mock-data/Chỉ để nạp database trống lần đầu và làm dataset cho hệ thống ngoài; không phải nguồn dữ liệu lúc chạy
Lưu ýChỉ chạy một trong hai API (mock Node hoặc .NET) ở cổng 3000 — hai app FE đều mặc định trỏ vào đó.

3 Database

Cần hai role đăng nhập khác nhau — đây là nguyên tắc của tài liệu kiến trúc: role ứng dụng không được bỏ qua RLS, tác vụ đồng bộ/bảo trì dùng role riêng.

RoleThuộc tínhDùng choBiến môi trường
cms_appLOGIN · NOBYPASSRLSMọi request nghiệp vụDATABASE_URL
cms_adminLOGIN · BYPASSRLS · chủ sở hữu databaseÁp lược đồ, nạp dữ liệu mẫu, sao lưu/phục hồi, worker outboxDATABASE_ADMIN_URL
  1. Tạo role và database (bằng superuser). Đổi mật khẩu ngay trong lệnh — đừng dùng mật khẩu dev.
    bash
    sudo -u postgres env DB_NAME=euni_cms \
  ADMIN_PASSWORD='<mật-khẩu-cms_admin>' APP_PASSWORD='<mật-khẩu-cms_app>' \
  ./database/v2/setup-dev.sh
  2. Áp lược đồ — có hai cách, chọn một.
    • Tự động (mặc định): API tự chạy schema.sql + amendments.sql khi khởi động (idempotent, có khóa nên nhiều instance khởi động cùng lúc vẫn an toàn).
    • DBA chạy tay: đặt DB_MIGRATE=false cho API rồi chạy:
      bash
      PGPASSWORD='<mật-khẩu-cms_admin>' psql -h <host> -U cms_admin -d euni_cms -v ON_ERROR_STOP=1 \
  -f database/v2/schema.sql -f database/v2/amendments.sql
  3. Dữ liệu ban đầu. Lần khởi động đầu, nếu database chưa có dữ liệu, API nạp dữ liệu mẫu từ mock-data/ (2 tenant humg, cntt, tài khoản mẫu…). Với môi trường thật, dữ liệu này đến từ đồng bộ danh bạ/đơn vị; xem mục Xử lý lỗi nếu muốn khởi tạo trống.
  4. Kiểm tra RLS đã hoạt động bằng chính role ứng dụng — không có ngữ cảnh tenant thì không thấy dòng nào:
    bash
    PGPASSWORD='<mật-khẩu-cms_app>' psql -h <host> -U cms_app -d euni_cms -At -c "select count(*) from cms.news"
# kết quả mong đợi: 0
Không làmKhông cấp BYPASSRLS cho cms_app và không đặt DATABASE_URL = DATABASE_ADMIN_URL: khi đó RLS không còn bảo vệ tenant.
Sao lưu databaseNgoài tính năng sao lưu trong CMS (xuất JSON toàn bộ dữ liệu), cần pg_dump định kỳ ở tầng hạ tầng: pg_dump -Fc -d euni_cms -n cms. Bảng audit_logs là partition theo tháng — gọi select cms.ensure_audit_partition(current_date + interval '1 month') mỗi tháng (API tự tạo tháng hiện tại và tháng sau lúc khởi động).

5 Build và chạy

Cách A — chạy trực tiếp (systemd)

  1. Publish
    bash
    dotnet publish src/HUMG.CMS.Api -c Release -o /opt/euni-api
ls /opt/euni-api/mock-data | head -3           # dữ liệu mẫu đi kèm bản publish
ls /opt/euni-api/contract                      # openapi.json (phục vụ ở /docs/openapi.json)
  2. Tạo file môi trường /etc/euni-api.env (quyền 600, chủ sở hữu là user chạy dịch vụ):
    /etc/euni-api.env
    PORT=3000
HOST=127.0.0.1
API_LOG=false
BASE_PATH=/euni-api
CORS_ORIGINS=https://portal.humg.edu.vn,https://cms.humg.edu.vn
DATABASE_URL=Host=db.noi-bo;Database=euni_cms;Username=cms_app;Password=...
DATABASE_ADMIN_URL=Host=db.noi-bo;Database=euni_cms;Username=cms_admin;Password=...
AUTH_MODE=oidc
OIDC_AUTHORITY=https://id.humg.edu.vn
OIDC_AUDIENCE=cms-api
STORAGE_PROVIDER=s3
S3_ENDPOINT=http://minio.noi-bo:9000
S3_ACCESS_KEY=...
S3_SECRET_KEY=...
  3. Dịch vụ systemd /etc/systemd/system/euni-api.service:
    systemd
    [Unit]
Description=HUMG eUni cms-api
After=network-online.target postgresql.service

[Service]
WorkingDirectory=/opt/euni-api
ExecStart=/usr/bin/dotnet /opt/euni-api/HUMG.CMS.Api.dll
EnvironmentFile=/etc/euni-api.env
User=euni
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
    bash
    sudo systemctl daemon-reload && sudo systemctl enable --now euni-api
journalctl -u euni-api -f          # lần đầu: áp lược đồ + nạp dữ liệu mẫu, rồi in "eUni API gateway (.NET)"

Cách B — Docker

Dockerfile và docker-compose.yml (API + PostgreSQL + MinIO) có sẵn trong euni-api-dotnet/. Truyền cấu hình qua biến môi trường như bảng ở mục 4.

bash
docker build -t euni-api .
docker run -d --name euni-api -p 127.0.0.1:3000:3000 --env-file /etc/euni-api.env euni-api
Chưa kiểm chứngdocker-compose.yml và image chưa được chạy thử (môi trường dựng repo không có Docker). Hãy chạy thử ở môi trường staging trước.

Cập nhật phiên bản

  • Triển khai bản mới → khởi động lại dịch vụ. Lược đồ được áp lại an toàn (idempotent); không có bước migrate riêng.
  • Nhiều instance chạy song song được (khóa advisory khi khởi động; worker outbox dùng SKIP LOCKED), nhưng API hiện xử lý tuần tự từng request trong mỗi instance.

6 Gateway và hai website

Reverse proxy (Nginx)

Cần chuyển nguyên header Host/X-Forwarded-Host — tenant được suy ra từ tên miền khi không có X-Tenant — và cho phép upload tệp lớn.

nginx
location /euni-api/ {
    proxy_pass http://127.0.0.1:3000;            # giữ nguyên tiền tố: API nhận cả có và không có BASE_PATH
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    client_max_body_size 50m;
}

Trỏ hai website vào API

Hai app gọi ${NEXT_PUBLIC_API_GATEWAY_URL}/<service>/api/v1/…. Đặt biến này tại thời điểm build rồi build lại:

Biến (euni-admin và euni-public)Giá trị ví dụ
NEXT_PUBLIC_API_GATEWAY_URLhttps://api.humg.edu.vn/euni-api (= gateway + BASE_PATH)
NEXT_PUBLIC_AUTH_MODEoidc khi dùng Identity Server; mock chỉ để thử
NEXT_PUBLIC_TENANT_HOSTS · NEXT_PUBLIC_DEFAULT_TENANTTên miền → tenant (website Khoa/Phòng). Tên miền mới có thể thêm trong CMS, không cần build lại
Không cần sửa mãKhông dòng nào của euni-admin/euni-public phải đổi: hợp đồng API được giữ nguyên và đã kiểm chứng (118 kiểm tra hành vi, 724 yêu cầu đối chiếu, 25 kịch bản đồng bộ với website thật).

7 File media (MinIO / S3)

  1. Tạo user MinIO có quyền đọc/ghi/xóa trên bucket cms-public (API tự tạo bucket nếu chưa có và user được phép).
  2. Đặt STORAGE_PROVIDER=s3, S3_ENDPOINT, S3_ACCESS_KEY, S3_SECRET_KEY; S3_BUCKET (mặc định cms-public), S3_FORCE_PATH_STYLE=true với MinIO.
  3. Không cần mở bucket ra Internet: API phục vụ file qua đúng URL tương đối cũ cms-api/uploads/<object_key>, nên ảnh trên website không đổi đường dẫn.

Object key có dạng {tenant}/yyyy/MM/{uuid}.{ext}; thông tin file nằm ở bảng cms.media. Nếu ghi database lỗi sau khi đã upload, API tự xóa file vừa tải lên (bù trừ); nếu việc xóa cũng lỗi thì lỗi được ghi ra stderr và trả về, không bị bỏ qua.

Chưa cóBucket cms-private (đính kèm thông báo, presigned URL) chưa làm. Chuyển file đang lưu đĩa sang MinIO: sao chép nội dung thư mục uploads/ vào bucket theo đúng object_key trong bảng cms.media.

8 Đăng nhập: Identity Server

Ở AUTH_MODE=oidc, API chỉ kiểm tra token do Identity Server cấp (chữ ký lấy từ {OIDC_AUTHORITY}/.well-known/openid-configuration, issuer, audience, hạn dùng). Các endpoint đăng nhập của mock (/auth-api/…/login, refresh) trả 501. Không đổi cấu hình SSO hay gateway.

Cần có ở Identity ServerChi tiết
AudienceAccess token có aud = cms-api (biến OIDC_AUDIENCE)
RoleĐọc từ claim roles, realm_access.roles và resource_access.<OIDC_ROLE_CLIENT>.roles. Realm role: student lecturer staff manager parent applicant alumni; client role: cms.viewer cms.author cms.reviewer cms.editor cms.admin
Claim bổ sungtenants (mặc định humg), units (mã đơn vị), staff_code, student_code, name, email
Phân quyền chi tiếtKhông cấu hình trên SSO: CMS tự quản bằng bảng grants (trang, chuyên mục, đơn vị, bản ghi) tại màn hình Phân quyền
Cần xác nhậnTên claim thật của Identity Server chưa được thử với hệ thống thật (mới thử bằng khóa RSA cục bộ). Nếu khác, chỉnh OidcTokenService.ToPrincipal. Người dùng phải có grant tương ứng trong CMS mới thấy được trang quản trị của tenant.
Quan trọngKhông dùng AUTH_MODE=mock ở môi trường thật: mật khẩu dev Humg@2025 và khóa HS256 là công khai trong repo.

11 Xử lý lỗi thường gặp

API thoát ngay lúc khởi động, log có permission denied / must be owner

DATABASE_ADMIN_URL phải là role sở hữu database/schema cms (cms_admin). Nếu schema đã được tạo bởi superuser, chuyển chủ sở hữu hoặc chạy lược đồ bằng đúng role này.

extension "ltree" is not available hoặc không tạo được extension

Cài gói contrib của PostgreSQL (postgresql-16 trên Debian/Ubuntu đã gồm). Extension là loại "trusted" nên chủ sở hữu database tạo được; nếu vẫn lỗi, superuser chạy CREATE EXTENSION unaccent, pg_trgm, ltree trong database.

Mọi request đọc đều rỗng / 403 "Không được ghi dữ liệu của trang này"

Gần như chắc chắn DATABASE_URL đang là role không đúng, hoặc tenant gửi lên (header X-Tenant/tên miền) không có trong cms.tenants (khi đó API trả 400 "Tenant … không tồn tại hoặc đã tắt"). Kiểm tra select id, is_active from cms.tenants.

Trình duyệt báo CORS

Origin của website chưa nằm trong CORS_ORIGINS (so khớp chính xác scheme + host + cổng). Header tùy biến X-Tenant, If-Match đã được cho phép.

Ảnh vỡ sau khi đặt sau gateway

URL media là đường dẫn tương đối (cms-api/uploads/…) được FE ghép vào NEXT_PUBLIC_API_GATEWAY_URL; đảm bảo biến này gồm cả tiền tố gateway và proxy chuyển /cms-api/uploads/ về API.

Trả 409 "Dữ liệu bị trùng …" hoặc 422 "Dữ liệu không hợp lệ …"

Vi phạm ràng buộc database (trùng slug/mã, tham chiếu không tồn tại, giá trị ngoài danh sách). Đây là lỗi của dữ liệu gửi lên, không phải lỗi hệ thống; tên ràng buộc nằm trong thông báo.

Muốn khởi động với database trống, không nạp dữ liệu mẫu

Hiện chưa có công tắc. Cách làm: áp lược đồ bằng psql (DB_MIGRATE=false), tự tạo dòng cms.app_meta(key='schemaVersion') để API coi như đã khởi tạo, rồi đồng bộ tenant, đơn vị, danh bạ vào cms.tenants, cms.org_units, cms.user_directory. Nên bổ sung công tắc này khi có nguồn đồng bộ thật.

Sự kiện outbox kẹt (attempts = 8, processed_at rỗng)

Đọc last_error, khắc phục nguyên nhân, rồi đặt lại: update cms.outbox set attempts = 0, available_at = now() where id = ….
